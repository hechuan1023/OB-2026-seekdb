# SQ8 dot-product candidate scan

Date: 2026-11-13

This experiment changed only the self-written SQ8 candidate scan used when a
request explicitly selects `ann`. Exact mode, transaction handling, durable
storage and recovery paths were not changed.

## Change

The previous candidate score computed this integer sum for every row:

```text
sum((row_code - query_code) ** 2)
```

The candidate uses the algebraically equivalent identity:

```text
row_norm + query_norm - 2 * dot(row_code, query_code)
```

Row norms are computed once while the SQ8 index is built. The AVX2 scan now
computes dot products, and reconstruction of the integer distance happens once
per row. Integer arithmetic preserves the previous candidate ordering exactly.
The selected candidates are still re-ranked with the float32 kernel and the
returned distances are still recomputed with the ordered-double kernel.

## Direct kernel A/B

The direct test used two shared libraries in one Linux container, 10,000 rows,
128 dimensions, 500 queries, K=10 and 16 SQ8 candidates. Seven alternating
rounds compared the previous squared-difference loop with the dot-product
candidate.

| Selection | Baseline median | Candidate median | Paired candidate / baseline | Candidate faster |
| --- | ---: | ---: | ---: | ---: |
| Unfiltered | 41.511 ms | 39.517 ms | 0.979965 | 4/7 |
| 2,000-row filter | 14.066 ms | 13.856 ms | 0.985036 | 4/7 |

The kernel direction was consistently below 1.0 in the paired median, while
the small round counts show that host scheduling still affects individual
rounds.

## End-to-end JSONL A/B

Each run used the Docker JSONL protocol, 10,000 rows, 128 dimensions, 1,000
TopK queries, K=10, 500 filtered and 500 unfiltered queries. Baseline and
candidate images alternated for seven pairs under each of three seeds. Every
returned ID, order and distance was checked against exact truth.

| Seed | Paired query ratio | Candidate faster | Filtered Recall@10 | Unfiltered Recall@10 | Bad results |
| --- | ---: | ---: | ---: | ---: | ---: |
| 20261113 | 0.999568 | 4/7 | 1.0 | 1.0 | 0 |
| 20261114 | 0.991872 | 4/7 | 1.0 | 1.0 | 0 |
| 20261115 | 0.863996 | 6/7 | 1.0 | 1.0 | 0 |

The median of the three paired run medians was `0.991872`. The large variation
between seeds is host and request-path noise, so these local diagnostics do
not establish an official T, B, M or E result.

## Resource and correctness checks

- Physical writes were unchanged at `6,037,504` bytes in the measured runs.
- Peak memory increased by about 40 KiB because the SQ8 index stores one
  `int32` row norm per row.
- Windows unit tests passed `183/183`.
- Docker unit tests at 256 MiB passed `183/183`.
- The official public JSONL protocol checker passed `20/20`.
- The 64 MiB lifecycle suite passed `4/4`, including statement atomicity,
  rollback, acknowledged-commit SIGKILL recovery, uncommitted rollback, EOF
  and SIGTERM restart.
- No container was OOM-killed.

## Scope and limitations

- The optimization affects explicit `ann` requests only. `exact` remains the
  default and continues to use the exact flat scan.
- SQ8 is a candidate filter; final IDs and distances are still checked with
  exact kernels. The tested distributions retained Recall@10 of `1.0`, but
  hidden official data still needs to satisfy the published recall threshold.
- The index is derived from the snapshot and is rebuilt after vector or
  membership changes. This experiment does not add incremental ANN
  maintenance.
- Measurements used Docker Desktop with a two-CPU, 256 MiB cgroup and a busy
  host. They are useful for A/B direction and correctness, not for predicting
  the platform's official score.
