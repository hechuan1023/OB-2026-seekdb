# OpenMP 精确 TopK 优化记录

日期：2026-11-13

本记录对应测试分支 `perf/iterative-optimization` 中包含本文件、Dockerfile、原生内核和测试的同一个 Git 提交。无过滤并行基线为提交 `a1897ff9bcc7727539579685395e00331253953c`；过滤集候选以已提交的 `49ed6fb72b3f3385344541deaeb46adcc575fed8` 镜像为基线。这些是本地诊断结果，不是官方 T、B、M 或 E。

## 改动

- `native/exact.cpp` 增加 `mv_topk_f32_exact_omp`。无过滤大表按连续行区间拆给 2–4 个线程；大过滤集按候选位置区间拆分。每段保留 K+1 个候选，合并后按距离和主键排序，再用原来的有序 double 循环计算返回距离。
- `minivectordb/vector_index.py` 从 `/sys/fs/cgroup/cpu.max` 读取可用的 CPU 配额，限制为 1–4 线程。无过滤查询在记录数至少 4096 时、过滤查询在候选集至少 1024 行时进入 OpenMP 路径；小表、小过滤集和单 CPU 配额继续使用原单线程路径。
- `Dockerfile` 使用 `-fopenmp -pthread` 编译，并把构建阶段实际使用的 `libgomp.so.1.0.0` 复制到运行镜像，建立 `libgomp.so.1` 链接。
- 新增差分测试覆盖 7/128 维、K=1/10/11、完全并列时主键排序、大过滤集并行、小过滤集回退及单线程结果一致性。

未采用的 NSW 图实验代码已从 `native/exact.cpp` 删除，未进入本提交。

## 取舍与限制

- 该方案只并行扫描阶段；过滤仍在并行距离计算前完成，合并后继续使用统一距离与主键排序，不改变过滤、事务和排序语义。
- 1 CPU、缺少 `cpu.max`、小表或旧原生库都会安全回退，不依赖多线程才能工作。
- OpenMP 增加了 `libgomp` 运行时文件和少量峰值内存；无过滤容器内峰值内存约 103 MiB，大过滤集端到端峰值变化约 0.03%。
- 每次查询仍有 OpenMP 区域启动和候选合并开销，因此只在大无过滤表或至少 1,024 行的过滤集启用。
- 正式 CPU 配额、冷缓存、驱动效率和 I/O 统计仍以平台为准。本记录不能替代正式准入或性能排名。
