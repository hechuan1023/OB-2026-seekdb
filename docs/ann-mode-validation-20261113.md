# ANN 模式端到端验证记录

日期：2026-11-13

本记录验证测试分支 `perf/iterative-optimization` 中已有的自研 SQ8 候选过滤路径。它不改变默认 `exact` 模式，也不改变 Docker 或测试驱动协议；`ann` 只在请求显式指定时使用。

## 方法

使用 Docker JSONL 协议、10,000 条记录、128 维向量、每批 100 行提交、1,000 次 TopK 查询，其中一半带普通列等值过滤。每个模式使用独立空数据卷，exact 与 ann 在同一轮交替执行；每轮逐条核对完整主键、距离、排序和去重。

两个随机种子分别运行 5 对和 3 对，共 8 对：

| 种子 | 对数 | exact 查询中位数 | ann 查询中位数 | 配对中位比值 | ann 更快 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 20261110 | 5 | 1.608043 s | 1.583789 s | 0.941255 | 4/5 |
| 20261113 | 3 | 1.587549 s | 1.422450 s | 0.893812 | 3/3 |

两组合并后的中位数：

| 指标 | exact | ann | ann/exact |
| --- | ---: | ---: | ---: |
| 查询总耗时 | 1.599554 s | 1.487336 s | 0.929844 |
| 过滤查询 | 0.766279 s | 0.730698 s | 0.953568 |
| 无过滤查询 | 0.835768 s | 0.756638 s | 0.905320 |
| 写入耗时 | 1.507318 s | 1.485719 s | 0.985671 |
| 容器峰值内存 | 36,001,792 B | 37,263,360 B | 1.035042 |
| 物理写入 | 6,037,504 B | 6,037,504 B | 1.0 |

配对查询耗时比值的 8 对中位数为 `0.933019`，ann 在 `7/8` 对更快。写入和物理写入差异处于宿主噪声范围，不能归因于 ann；峰值内存增加约 3.5%，来自 SQ8 码本和候选状态。

## 正确性

- 两种随机种子、8 对运行中，过滤和无过滤 Recall@10 均为 `1.0`。
- 每轮返回 ID 无重复，ID 集合和顺序与独立暴力真值一致。
- 返回距离与真值逐条一致；ann 候选最终仍由精确 float32 内核和 double 距离复核。
- 数据写入后重启、索引重建和事务路径未改变，完整回归仍以 `183/183`、官方 JSONL `20/20` 和 64 MiB 生命周期结果为准。

## 取舍与限制

- `ann` 是显式模式；默认请求仍走 `exact`，不会用近似结果替代精确语义。
- SQ8 只在基准形状和分布满足条件时启用；分布跨度不均衡或候选集过小时回退到精确路径。
- 本地 JSONL 管道和 Docker Desktop 调度仍占查询端到端时间的大部分，结果不能直接换算官方 T、B、M 或 E。
- 正式性能配置是否选择 `ann` 由提测参数决定；本记录不改变协议或默认模式。
