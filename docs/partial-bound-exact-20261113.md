# 有界精确 TopK 候选扫描（2026-11-13）

本实验在 `perf/iterative-optimization` 的 `d7cea191b` 基线上，为
128 维 exact TopK 候选扫描增加一个部分距离下界。目标是减少明显不可能进入
TopK 的行的剩余维度计算，同时保持过滤、距离并列、主键顺序和最终精确复核
语义不变。

本页记录的是 Docker Desktop 本地对照，不是官方 T/B/M、E、Recall 或正式
准入结果。

## 实现

- 现有 float32 AVX2/FMA 内核先计算平方距离并选出有限候选，随后仍由原有
  float32 精确内核和有序 double 距离复核处理最终结果。
- 每行处理完前 64 维后，已经得到的非负平方差之和是完整平方距离的下界。
- 只有当前 K 个候选已满，且
  `partial_sum > kth_distance * 1.001 + 1e-30` 时，才提前结束该行扫描。
- 靠近边界的行继续计算完整距离；最终候选、并列主键规则和边界回退逻辑均未
  改变。
- 0.1% 余量用于覆盖 float32 累计误差。各项均为非负平方差，不存在正负项
  相消；阈值未建立、维度不足或非 AVX2 路径时保持原行为。

## 被拒绝的多检查点版本

首个版本在 32、64、96 维各检查一次。完整 JSONL 路径的配对中位候选/基线
比值为 `1.018692`，说明额外分支和阈值读取抵消了剪枝收益，因此回退。只保留
64 维单检查点后重新测量。

## 内核 A/B

负载为 10,000 行、128 维、K=10、500 次查询，交替运行 7 轮。表中“配对
比值”是逐轮候选/基线比值的中位数，不是两个汇总耗时的直接相除。

| 集合 | 基线中位 | 候选中位 | 配对比值 | 候选更快轮次 |
| --- | ---: | ---: | ---: | ---: |
| 无过滤 | 47.838 ms | 46.030 ms | 1.003035 | 3/7 |
| 2,000 行过滤 | 14.771 ms | 14.465 ms | 0.961289 | 4/7 |

无过滤内核的配对结果不稳定，过滤集合的收益更明确。因此不能只依据内核中位
耗时宣称整体提速，必须继续看完整 JSONL 路径。

## 端到端 JSONL A/B

负载为 10,000 行、128 维、K=10、1,000 次查询，其中一半带普通列等值过滤。
每个种子交替运行 7 对基线镜像 `minivectordb:sq8-dot-20261113` 和候选镜像
`minivectordb:partial-bound64-20261113`。

| 种子 | 总查询比值 | 有过滤比值 | 无过滤比值 | 总查询候选更快 |
| --- | ---: | ---: | ---: | ---: |
| 20261113 | 0.995489 | 0.978229 | 1.011215 | 4/7 |
| 20261114 | 0.989624 | 0.990613 | 0.988737 | 4/7 |
| 20261115 | 0.973818 | 0.953517 | 0.992675 | 4/7 |

三次运行的配对中位比值中位数为 `0.989624`。21 对端到端结果均逐条核对 ID、
顺序和距离，全部一致。物理 I/O 未观察到变化；候选/基线峰值内存比值约为
`1.0001` 到 `1.0007`。

## 结论与边界

保留 64 维单检查点：三种子端到端总查询比值的中位数为 `0.989624`，过滤场景
稳定受益，无过滤场景接近中性，I/O 与内存没有可测回退。该优化只作用于
AVX2/FMA 的 exact TopK 候选扫描，不改变 SQL、事务、恢复、过滤顺序或最终精确
结果；它也不能单独解释或预测官方性能 E。
