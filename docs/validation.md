## 结果

优化阶段 Windows **54 项测试全部通过，耗时 33.553 秒**，包括原生索引与 Python 精确执行器对照、事务、失败语句、强杀恢复、极端 float32、数值边界回退、直接主键查询和有界内存路径。见 [完整输出](r2-validation-tests.txt)。后续 Linux 加入公开样例的两种执行路径后，64 项测试全部通过，耗时 12.352 秒。

相同的 10,000 条、128 维、200 次查询负载，分别运行优化前后三轮：查询中位耗时从 14.763173 秒降到 1.108220 秒，约 **13.32 倍**；写入中位耗时从 15.695851 秒降到 4.064104 秒，约 **3.86 倍**。

这些是本地对照结果，不是正式 Linux cgroup 指标、E 或赛事分数。

## 本轮修改

- SQL 分句按片段跳过字符串和注释，减少逐字符对象；入口只解析一次。
- 向量批量转换为 array('f')，仍检查数值类型、有限性、维度和 float32 溢出。
- 自研 C++17 精确扫描、补偿求和和 K+1 候选堆，扫描磁盘映射的连续 float32 与主键文件。
- 先计算符合 WHERE 的候选位置；位置缓存有界，数据变化时失效，不缓存查询答案。
- 边界距离过近时回退完整 Python 精确扫描；返回候选均用 math.dist 复算并重排。
- 事务修改、失败语句、提交和回滚处理派生索引失效；重启在 READY 前重建。
- 主键等值条件继续直接定位；大 K、大过滤集合、复杂排序和未编译内核均保留通用路径。

## 三轮对照方法

基线为本轮开始前复制到 `.local-baseline-r2` 的源码快照，核心文件 SHA256 与原始记录一致；该本地快照被 Git 忽略，不是一个新的正式提交。两组均使用同一个 workload_version=2 驱动、种子 20261109、10,000 条、128 维、每批 100 条自动提交、K=10、200 次查询且一半带等值过滤。

驱动预先生成相同 SQL 批次，写入计时不再包含 JSON／SQL 生成；统一预热前四条查询，建索引和预热耗时另记。每轮使用独立进程与空数据目录，各个 benchmark 进程不并发运行。它仍没有平台的 CPU 配额、冷缓存控制、物理 I/O 采集或 cgroup 内存限额。

每轮逐条检查 ID、数量、顺序和距离；有过滤、无过滤两组 Recall@10 均为 1.0；重启后逐条核对 ID、标签、向量内容。基线三轮源码一致，最终优化三轮及下方最终完整负载与当前核心源码摘要一致。中间开发结果另存，未混入中位数。

| 指标 | 优化前中位数 | 优化后中位数 |
| --- | --- | --- |
| 批量写入秒数 | 15.695851 | 4.064104 |
| 200 次查询秒数 | 14.763173 | 1.108220 |
| 建索引加统一预热秒数 | 0.696951 | 0.560867 |
| 恢复至 READY 秒数 | 0.285855 | 0.396478 |
| Windows 峰值工作集 MiB | 29.99 | 36.41 |

优化增加了派生向量文件：测量结束时数据目录文件大小从 6,989,103 字节增至 12,189,103 字节，其中向量和主键文件共 5,200,000 字节。文件大小不是磁盘 I/O 指标 B；Windows 工作集不是 cgroup memory.peak。索引映射的页缓存与重建写入仍需正式环境统计。

恢复中位耗时有所上升，原生快照需要在 READY 前重建。高频更新会使快照失效并在后续检索重建，当前还不是增量向量索引。

## 完整负载与回退

换用种子 **20261110**，最终源码执行 1,000 次查询：写入 4.028142 秒，查询 6.320273 秒，恢复 0.396038 秒；两组 Recall@10 均为 1.0，重启内容核对通过。见 [完整负载](r2-final-full.json)。该负载与 200 次对照的种子、查询数不同，不用于计算上面的倍数。

关闭原生内核后，最终源码的 100 次查询回退测试也全部通过，写入 3.284640 秒、查询 3.231105 秒；见 [Python 回退结果](r2-final-portable.json)。

## 内存与故障验证

原存储测试保持通过：WAL 大于 32 MiB，排序和记录缓存各 256 KiB，恢复和排序的 Python 分配峰值低于 8 MiB。

新增原生测试构建 20,000 条 128 维向量，向量文件 10,240,000 字节；关闭记录缓存、排序预算 64 KiB，索引构建与精确查询的 tracemalloc 峰值低于 2 MiB。tracemalloc 不包含 mmap 页缓存、全部运行时或 C++ 分配，不能当作进程或容器总内存上限。

新增故障场景：构建派生向量文件途中终止且未输出 READY；事务内查询生成了未提交快照后强杀。两者重启都从已提交记录重建，未观察到未提交记录泄漏。
