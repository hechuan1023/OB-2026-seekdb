# 从 0791cba 出发的性能实验

2026-11-11，以 `0791cba5ceec488e9fc2588d2f87da150cece21a` 为基线，在独立分支实施：小快照（最多 8 MiB）使用内存、批量插入每条语句记录一次集合变更、主键和距离投影从快照取值并用 `math.dist` 复核。保留 16 MiB 默认行缓存。超过快照阈值仍走原有文件映射路径。

本次 Linux Docker 容器为 2 CPU、256 MiB、禁用 swap；使用独立空数据卷，数据与查询种子 20261110。每个版本按固定顺序交替运行三轮，写入 10,000 条 128 维向量，每批 100 条自动提交；随后建立索引，运行 1,000 次精确 TopK（K=10，一半有等值过滤）。每条查询在宿主机以 `math.dist` 独立计算真值，并核对主键、顺序及距离；完整字段场景额外核对标签与向量。写入计时包含宿主端生成输入开销；查询计时不含索引准备。以下为三轮中位数，非官方 E：

| 指标 | 基线 | 候选 | 说明 |
| --- | ---: | ---: | --- |
| 5 种过滤值，主键和距离查询 | 2.183 s | 2.146 s | 快约 1.7% |
| 同场景写入 | 2.718 s | 2.738 s | 慢约 0.7% |
| 同场景容器内存峰值 | 35.15 MiB | 35.02 MiB | 中位数 |
| 600 种过滤值，完整字段查询 | 3.777 s | 3.849 s | 慢约 1.9% |
| 同场景写入 | 2.712 s | 2.728 s | 慢约 0.6% |
| 同场景容器内存峰值 | 35.90 MiB | 36.60 MiB | 中位数 |

本地一次性采集的 `io.stat` 中设备 8:64 的 wbytes 在 5 值场景分别为 13,811,712 和 8,609,792，600 值场景为 13,828,096 和 8,626,176；未核实设备归属、未控制冷缓存，且在容器关闭前采集，因此不能直接作为正式 B。三轮详情见 `perf-0791-id.json` 和 `perf-0791-full.json`。实验未重启核验每条数据，持久性由下列独立测试覆盖，不能替代正式 benchmark 的全部校验。镜像标签分别为 `minivectordb:audit-0791` 和 `minivectordb:from-0791-optimized`。

复现入口：`python tests/perf_pair_id.py --image minivectordb:audit-0791 --compare minivectordb:from-0791-optimized --groups 5 --queries 1000 --rounds 3 --output result-id.json`；将脚本改为 `tests/perf_pair_full.py`、groups 改为 600 可运行另一组。需先分别从两个源码版本构建镜像。这里结果受宿主负载、执行顺序和缓存影响，不能推算正式 E，也没有证明整体性能全面提升。

验证：实际镜像原生内核的 `python -m unittest discover -v` 共 119 项通过；官方 `protocol_check/run.py` 在 WSL/Linux 运行 20 组公开用例全部通过，结果见 `perf-0791-public-result.json`。Windows 直接运行官方驱动时因缺少 `os.set_blocking` 和 `os.killpg` 失败，随后使用 Linux 重跑成功。

64 MiB、禁用 swap 的容器压力测试：18,000 条、1,024 维，向量文件 73,728,000 字节，大于内存限制；精确与过滤查询、长事务失败和回滚、提交、重启、脏快照后 SIGKILL 与恢复检查通过，`oom_kill=0`，`memory.peak=67,108,864`。这是正确性压力测试，进程和测试器共同计入，峰值已触及限制，不能据此推断所有数据分布下的资源安全。

正式用例、官方性能指标和排名仍以平台为准。Agent 对实现与实验的说明不构成学生独立学习的证据。
