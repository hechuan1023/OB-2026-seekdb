# MiniVectorDB 性能优化复盘（2026-11-11）

本文件复盘 `perf/iterative-optimization` 测试分支的优化循环。所有数字均为本机 Docker Desktop 上的本地测量，不是官方 T/B/M 或赛事 E。正式分支 `2026-competition-round2` 在本轮期间未修改。

## 保留的优化

| 阶段 | 改动 | 主要测量 | 代价 |
| --- | --- | --- | --- |
| 内存快照 | 小数据集向量快照驻留 `bytearray`，大数据集仍用文件 + mmap | 数据设备 wbytes 13.81 → 8.61 MB（-37.6%） | 匿名内存不可回收；聚类分布 M +2% |
| 内核内联 | 8 通道双精度归约内联进克隆的 `mv_topk` | 内核 0.493 → 0.327 ms；select 0.746 → 0.457 ms | 无 |
| FMA 内核 | 独立 `mv_topk_fma` + 运行时选择，保留可移植回退 | 内核 0.327 → 0.294 ms；5/600 值查询 -7.8%/-6.3% | 末位舍入不同，由 1e-12 边界保护覆盖 |
| 匿名主键索引 | cgroup 限额 ≥128 MiB 时索引驻留匿名内存 | wbytes 8.61 → 6.63 MB（-23.0%） | 64 MiB 容器仍用文件路径 |
| 过滤预算 | 1 MiB → 1.5 MiB，600/2000 组全部缓存 | 2000 组过滤查询 -14.8% 到 -24.7%（三个种子） | 该分布 M +1.6% 到 +2.3% |
| 向量更新修补 | 向量 UPDATE 按 key 扫描快照并原位覆盖 | 10k 更新周期 6.36 → 2.76 s（-56.6%）；100k 2.1 倍 | 回滚失效快照；删除/插入仍重建 |
| BIGINT 转换 | 逐值正则校验改为 `isdecimal` | 10k 写入引擎 0.859 → 0.825 s（方向一致，幅度在噪声内） | 无 |
| Literal 表示 | frozen dataclass 改为 NamedTuple | 10k 写入引擎 0.878 → 0.839 s（约 4.5%，三次一致） | 无 |
| 查询验证快速路径 | 仅投影主键和距离时从快照读向量 | select 未过滤 0.404 → 0.358 ms（-11%）；过滤缓存 0.122 → 0.093 ms（-24%） | 仅适用于该投影形状 |
| 延迟槽位计算 | 原生路径跳过表达式哈希与槽位表 | select 未过滤 0.366 → 0.344 ms（约 -6%，部分噪声） | 无 |
| 结果行 JSON | 数值行手写格式化，其他回退 | 1.92 → 0.71 µs/行（输出逐字节一致）；5 值端到端中位 2.115 → 2.023 s（部分噪声） | 非数值行回退通用编码器 |
| INSERT 变更标记/列表推导 | 每语句一次变更标记，列表推导替代生成器 | 10k 写入引擎 0.892 → 0.834 s（7 对交替，约 -6.5%） | 无 |
| 提交 CRC 合并 | CRC 与 WAL 拷贝合并为一次读取 | 10k 写入引擎 0.861 → 0.839 s（7 对交替，约 -2.6%） | 头部校验和先占位、页脚前发布 |
| 记录长度传递 | 迭代器把记录长度传给 `_apply` | 10k 写入引擎 0.885 → 0.867 s（7 对交替，约 -2.0%） | 无 |
| 行缓存默认 4 MiB | 16 MiB → 4 MiB 默认 LRU 缓存 | memory.peak 36.7 → 31.8 MB（-13.3%）；10 组查询 +1.4%（噪声内）、5 组 -3.1%（噪声内） | 验证读盘增加，冷过滤扫描更慢；2 MiB 只再降 0.72 MB（-2.3%）而查询 +0.7%，不再采用 |
| WAL 行编码 | 自定义二进制行编码，旧 pickle 记录仍可读 | WAL 6.20 → 5.59 MB（-9.8%）；写入引擎 0.810 → 0.745 s（约 -8%） | 新增编码/解码路径，已覆盖恢复、事务、Unicode 和旧格式回退 |

## 测量并回退的候选

| 候选 | 结果 | 结论 |
| --- | --- | --- |
| 内存事务暂存 | 引擎与端到端均无稳定收益 | 回退 |
| 距离表达式保留 `array('f')` | `math.dist` 变慢，select 0.384 → 0.545 ms | 回退 |
| 首字符分派词法分析 | 解析仅快 3–4% | 回退 |
| 提交复用记录对象 | 0.875 vs 0.840 s 中位，无收益 | 回退 |
| 内联 `hash_key` 到 `_slot` | 7 对交替中位 0.876 → 0.883 s，方向不一致 | 回退 |
| 用记录长度替代 `tell()` | 4 对交替中位 0.825 → 0.864 s，方向不一致 | 回退 |
| INSERT 行解析内联 | 7 对交替方向不一致，收益在噪声内 | 回退 |
| 匿名覆盖索引 | 7 对交替中位 0.819 → 0.853 s，匿名映射缺页抵消文件调用节省 | 回退 |

## 未采用的候选

- **WAL 自定义格式/压缩**：预计节省约 0.6 MB B（约 10%），但改变持久化格式，恢复正确性风险高。
- **float32 粗排 + double 精排**：实现后真实路径测量反而更慢——float32 top-128 粗排 0.270 ms 已慢于 FMA 双精度 top-11 的 0.249 ms，再加 128 候选精排 0.026 ms，`select` 未过滤 0.335 → 0.65 ms。自动向量化的 float32 循环没有优于显式 FMA 双精度，且更大的候选堆增加开销；已回退。
- **ANN 索引**：内核已 0.29 ms，Python 开销约 0.1 ms；实现与维护风险高，exact 已满足召回。
- **删除/插入增量维护**：成员变化导致快照位置移动，需要有效性位图或重映射；正式性能负载为只插入。
- **行缓存缩减**：M 可能下降约 3 MB，但验证读盘增加，交换比不利。

## 验证矩阵

- Linux 容器完整 unittest：119 项通过。
- 官方 JSONL 握手 + 20/20 公开用例通过。
- 64 MiB、18,000 × 1,024 维压力测试：`oom` 与 `oom_kill` 均为 0。
- 64 MiB 资源探针（20,000 行 × 8 KiB payload，WAL 超过限额 2 倍）：在 vec-patch、namedtuple 和 record-length 镜像上加载与恢复通过，`oom=0`、`oom_kill=0`，15.28–16.24 s。
- 容器生命周期：SIGKILL 保留已确认提交、EOF/SIGTERM 回滚与同卷重启通过。
- 独立交叉测试：P0 19/19 与 180/180、P1 22/22、P2 166/166、P3 3 种子 0 失败、P4 103/103、P5 17/17、P6 41/41、P7 112/112、P8 170/170、P9 33/33。
- 100,000 × 128 行：文件路径生效，写入 16.34 s、建索引 0.745 s、20 次查询 0.678 s、峰值内存 156 MB。

## 不确定性与限制

- 本地 Docker Desktop 管道约 1.2–2 ms/查询，端到端查询差异常被噪声掩盖；配对驱动先运行候选，交换顺序会反转 600 值结论，因此端到端查询不作为主要证据。
- io.stat 设备归属、冷缓存和完整写回未核实，不能计算官方 B 或 E。
- 正式 E=459.878921 与 Agent Prompt 无效提示来自用户转述的平台结果，原因未确认；本轮未发起正式提测。
- 匿名快照/索引在内存受限时不可回收，聚类分布 M +2%；正式 M 口径需复核。
