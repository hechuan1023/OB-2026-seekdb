## 测量方法

基于 bb5 的 `tests/perf_pair_full.py` 临时副本 `.local-diagnose-paired.py`：增加 seed 参数并按 A-B、B-A、A-B 顺序交替；不修改数据库代码。Docker Desktop 的 Linux 容器，2 CPU、256 MiB、禁 swap、禁网络，每次新建数据卷；1 万行、128 维、每批 100 行自动提交、建索引，1000 条查询（500 条等值过滤，500 条无过滤），精确模式，投影 id、tag、vector 和距离，逐条对照独立真值。分别运行 seed 20261112/5 个过滤值与 seed 20261113/600 个过滤值；两个变量同时改变，不能将结果差异单独归因于任一变量。每场景两版本各三轮。查询没有统一预热，含首次过滤开销。

原始报告：`.local-diagnose-seed-20261112.json`、`.local-diagnose-seed-20261113-g600.json`；其中有每轮耗时、过滤首次查询、内存和原始 io.stat。运行命令为 `python -u .local-diagnose-paired.py --image minivectordb:diag-0791 --compare minivectordb:diag-bb5 --output <报告> --queries 1000 --groups <5或600> --rounds 3 --seed <20261112或20261113>`。

- 当前脚本的 SQL 拼接落在写入计时内；两版本相同，但并非纯数据库耗时；且进程、宿主机、Docker Desktop 缓存和后台负载可能影响结果。

- 相同容器内每轮输入随机生成及真值在宿主机事先准备；结果每次严格核对。现有场景未对正式 benchmark 的大批量重启内容做验证，不等于完整功能/资源回归。
