# OpenMP 批量向量解析优化记录

日期：2026-11-13

本记录对应测试分支 `perf/iterative-optimization` 中包含本文件、原生解析器和测试的同一个 Git 提交。基线为提交 `a1e13a5cfa9cc90f287b2234da112869af53e80f`；候选加入批量向量解析的 OpenMP 路径。以下均为本地诊断结果，不是官方 T、B、M 或 E。

## 改动

- `native/exact.cpp` 增加 `mv_parse_vectors_omp`。只有线程数大于 1 且批次至少 32 条时并行解析，每行仍调用原有 `mv_parse_vector`，并返回最小的非法向量下标。
- `minivectordb/native.py` 从 `/sys/fs/cgroup/cpu.max` 读取 CPU 配额，限制为 1–4 个工作线程；无法读取、单 CPU、旧原生库或小批次时继续使用原有顺序解析。
- 任一向量解析失败时，Python 仍丢弃整批临时结果并进入原有逐值回退路径，保留错误顺序、语句原子性和对非法输入的处理语义。
- 新增 100 条合法向量的逐项一致性测试，以及第 53 条非法时整批回退的测试。

该改动只作用于多行 INSERT 的向量文本解析，不改变 WAL、提交同步、恢复、过滤、距离计算、TopK 排序或事务可见性。

## 取舍与限制

- 并行度由容器 CPU 配额决定，不使用宿主全部 CPU；单 CPU 环境自动保持顺序解析。
- OpenMP 区域只覆盖相互独立的批量解析；失败后仍走原有逐值路径，因此不会把部分成功批次暴露给 SQL 执行器。
- 本地 Docker Desktop 同时运行其他容器，端到端结果存在宿主噪声。物理写入相同、单次微基准方向一致和 19/21 对端到端胜出共同支持保留该改动，但不能替代官方测量。
- 正式 CPU 配额、冷缓存、I/O 统计和端到端 E 仍以平台为准。
