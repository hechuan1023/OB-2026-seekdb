# MiniVectorDB 初版设计

## 设计范围

使用 Python 与 C++ 标准库自研存储与执行，不引入 SQLite、RocksDB、Faiss 等数据库或索引引擎。以完整事务语义和可验证恢复为基础，正式协议与 ANN 优化独立推进。

## 模块

| 模块 | 职责 |

| sql.py | 词法分析、SQL 子集解析，产生操作元组 |
| engine.py | 语义检查、类型转换、条件、可见性、SQL 执行 |
| storage.py | 记录编码、提交日志、磁盘哈希、事务暂存和恢复 |

| protocol.py | 自测输入分句与 TSV 输出 |
| __main__.py | 启动、参数、正常关闭、致命错误处理 |

## 记录与主键定位

行记录包含操作种类、表 ID、BIGINT 主键及完整行值；删除表示为值为 None 的内部墓碑，不是 SQL NULL。表定义和 flat 索引定义也是日志记录。

单条记录编码为四字节长度加 Python pickle protocol 5。VARCHAR 是 Unicode 字符串，向量为 `array('f')`。所有向量输入先检查维度与数值有限性，再转换为 float32；L2 通过 `math.dist` 对存储后值计算欧氏距离。

主键索引使用自研开放寻址哈希，槽位固定 24 字节，保存表 ID、主键、记录位置。正位置表示行，负位置表示墓碑，表 ID 为零表示空槽。哈希索引位于磁盘 mmap 文件，负载超过 60% 时倍增重建，不创建全表 Python 字典。

表扫描遍历当前主键槽位，读取有效记录，并与事务覆盖索引合并。主键等值条件直接定位，其他条件流式过滤。

已提交行可以进入有容量上限的 LRU 缓存，默认 16 MiB，按对象大小加保守条目开销估算。缓存键为不可变 WAL 位置；新版本使用新位置。事务暂存位置会在语句回滚后复用，因此不缓存暂存记录。返回向量投影时复制可变数组，避免调用方污染缓存。

## 事务与语句原子性

显式事务的修改写入 `transaction.stage`，`transaction.idx` 保存该事务对各主键的最终可见位置。读取先查覆盖索引，再查已提交索引。

每条修改语句开始时记录暂存文件长度和元数据快照。业务错误时截断到原长度，并从保留的暂存记录重建覆盖索引；此前成功语句仍可提交。自动提交语句失败则丢弃整个临时事务。

UPDATE／DELETE 先将本条语句匹配的记录流式写入临时文件，再逐条修改覆盖索引，避免扫描时修改哈希容量或看到本语句新写入的记录而重复处理。

ROLLBACK 丢弃暂存与覆盖索引，恢复元数据快照。当前实现允许 DDL 在显式事务内提交或回滚，这是待正式题包核对的语义选择。

## 提交流程

1. 对事务暂存内容分块计算 CRC32。
2. 向 WAL 追加 `TXN1` 头，包含 payload 长度和 CRC32。
3. 分块复制事务记录，再追加 `DONE` 尾部及重复长度。
4. 调用 `fsync` 同步 WAL；首次创建 WAL 时还在 POSIX 上同步数据目录。
5. 将本次提交应用到可重建的主键索引，关闭事务暂存。
6. 返回成功，由协议层刷新 stdout。

索引不是持久化真相，因此提交成功不依赖索引文件的 fsync。任意索引中间状态都可在重启时丢弃并重建。文件 I/O 故障为致命错误，程序退出后通过 WAL 恢复，不继续提供可能不一致的会话。

## 恢复流程

启动时重建空主键索引，然后流式扫描 WAL：只回放头、长度、CRC32、尾部均完整的事务。未完成尾部截断到最后一个完整事务边界。未提交的事务暂存文件被丢弃。

就绪信息必须在恢复完成后发出。恢复过程中即使再次强制终止，下次仍从权威日志重建，不依赖上次部分索引状态。

已确认提交必须恢复；未请求提交只存在暂存文件中，不会生效。已请求提交但未确认的事务，在完整尾部存在时可能生效，在写入未完成时不生效，均为整笔事务。

CRC32 用于发现不完整或异常记录，不提供磁盘损坏修复。完整帧校验失败会拒绝启动；这与题目不模拟磁盘损坏的范围一致。

## 日志压缩

提交完成后，如 WAL 达到默认 64 MiB 且超过有效行记录总长度的三倍，则流式写出当前表定义、索引定义和全部有效行。新 WAL 使用相同完整事务格式，写完并 fsync 后以原子 rename 替换旧 WAL，再同步目录，重建主键索引并清空旧位置缓存。

替换前旧 WAL 始终有效；替换后新 WAL 包含完整已提交状态。压缩不在活动事务中执行，删除槽位随索引重建回收。替换前后均设置了进程终止测试点；重启不依赖临时 checkpoint 文件。

有效行长度在提交回放及恢复时按旧位置和新位置增减，因此无需全表内存统计。压缩是同步的，可能增加提交延迟；同时保留新旧日志需要额外磁盘空间。

## 查询与排序

先应用 WHERE，再计算需要的距离或投影。排序键最后追加主键升序，保证普通排序并列和距离并列一致。

有 LIMIT 的排序维护最多 K 个当前候选；缓冲达到预算后把局部 TopK 写为有序段，再归并得到全局 TopK。无 LIMIT 时按预算拆段排序。各层满 16 段即合并，最终最多同时打开 16 个归并输入；所有临时段位于数据目录并在结束后删除。

精确向量检索始终基于当前可见行。`CREATE VECTOR INDEX` 注册 flat-exact 定义，并在原生内核可用时生成连续 float32 文件和主键文件；无编译器或原生库时保留通用执行器。

## 原生精确 TopK

`native/exact.cpp` 自行实现扫描与候选堆，通过 ctypes C ABI 调用，不依赖现成向量索引库。向量与主键映射在 /data，内核只读取这些映射，不将整个矩阵转换为 Python 对象或匿名内存副本。

普通过滤条件先确定候选位置集合，再由内核只扫描这些位置。缓存的是记录位置集合，不是查询向量或搜索答案。缓存全局有界，并与对应表的派生索引同时失效；大过滤集合使用流式执行器。

内核使用 double 补偿求和并返回 K+1 个候选，避免把 float32 的累加误差直接当成精确结果。有限 float32 输入和至多 65,536 维下，差值平方不会溢出或下溢 double；仍在第 K／K+1 个候选间保留宽于求和误差的相对 1e-12 防护区。落入防护区时回到 math.dist 全量精确路径。候选记录用 math.dist 复算并按距离、主键重排，输出与原执行器一致。不能仅靠最后排序修复候选集合错误，因此边界歧义必须回退。

修改语句执行前使该表索引及过滤缓存失效，失败语句也不会保留潜在旧候选；事务 COMMIT／ROLLBACK 清理派生快照。事务内查询可从覆盖索引和已提交数据重建快照，重启只从 WAL 恢复后的提交状态重建，READY 不早于重建完成。压缩 WAL 不改变行内容，已有向量快照不依赖 WAL 位置。

构建和查询均使用标准 C++17，禁用 fast-math 与浮点乘加合并。对并列、接近并列、极大及极小 float32、过滤值更新、失败语句、回滚、重复恢复和强杀后重建分别验证。

## SQL 输入处理

语句分隔器通过正则搜索结构符号并跳过整段字符串和注释，不再为每个 SQL 字符创建列表元素。入口复用一次解析结果，避免执行前重复词法分析。向量使用 array('f', values) 批量转换，仍在转换前拒绝非数值和非有限输入，转换后检查 float32 溢出。

## 需要继续改进的方向

压缩阈值调优、按负载优化记录布局、自研 ANN 和正式协议适配。已补充 Linux cgroup 64 MiB 限额下的大数据验证，见 docker-validation.md；本地分配测试和单个容器资源用例都不能代替正式资源约束验收。
