## 第二轮（同日，提交 423628d0a 之后）

剖析显示第一轮后查询热点分布：内核 41%、`storage.get` 链 35%（其中约 5 万次来自 5 个过滤条件首次扫描各遍历 10,000 位置，属一次性成本）、分词器降至 4%。

修改三项：

1. **`native/exact.cpp`**：补偿链 4 → 8 条（lane `j&7`）。先试 16 条：宿主机（MinGW/SSE2，无 target_clones）32 个累加器超出寄存器容量导致溢栈，基准回退 14.5%，**弃用**；8 条在宿主机与 4 条持平（剖析内核 0.352s vs 0.342s，噪声内），在容器 AVX2 clone 下静态查询中位 2.67→2.59ms 略优，故取 8。
2. **`minivectordb/storage.py` `DiskHash`**：小端平台用 `memoryview.cast('q')` 直接索引槽位（省去每次探测的 struct 元组构造），大端平台回退原 struct 路径；`_grow()` 重建 view、`close()` 先 release（避免 BufferError）。
3. **`minivectordb/engine.py` `convert()`**：向量元素类型检查改 `frozenset.__contains__` + `map`（消除每元素生成器帧；`type(True) is bool` 仍被拒）。

容器 benchmark（1 轮，同驱动，镜像 `minivectordb:cross-review` = `sha256:cf8e46f6…`，对比基线 `e125eda8`）：

**如实记录**：宿主机基准在同代码重复运行间有 ±3～10% 噪声，第二轮相对第一轮的单项差异多在噪声内（写入/恢复）；可靠的第二轮增量是容器静态查询中位 -3% 与写入/探测路径的结构性微优化。第二轮回归全绿：宿主机 106 套件 + 公开 40 + P0V 180 + P2 166 + P3 随机模型，容器 106 套件（19.8s）+ P2 166 + 生命周期 4 项 + 64MiB 压力（`oom_kill=0`）。

未采纳项（含原因）：手动解析向量 JSON（会改变 `[+1,2]` 等接受集，语义风险）；selection 过滤扫描重构（需表级内存映射，违反磁盘哈希设计约束）；去除每行 `sqrt`（改变并列守卫语义）。

## 三项修改（语义不变的依据）

1. **`minivectordb/sql.py`**：字符串/反引号 token 正则改为占有优先量词 `[^']*+(?:''[^']*+)*+`（Python 3.11+）。剖析显示 128 维查询向量（2.5KB 字面量）与 100 行大 INSERT（60KB）在旧 `'(?:''|[^'])*'` 下逐字符双交替回溯。转义语义不变（`''` 仍为引号转义）。
2. **`minivectordb/engine.py` `convert()`**：删除 float64 阶段的 `isfinite` 预遍历，改为 类型检查 → `array('f')`（捕获 float64→f32 溢出，`OverflowError`）→ `all(map(math.isfinite, result))` 单遍。NaN/Infinity/溢出/类型错误仍全部 `INVALID_VECTOR`，仅错误说明文字不同（协议未冻结错误文案）。
3. **`native/exact.cpp`**：单链 Kahan 补偿和（循环依赖，阻止自动向量化）改为 **4 条独立补偿链**：维度 `j` 归 lane `j&3`，各链内部严格串行，合并顺序固定 → 无论编译器选择何种 SIMD 宽度，结果**逐位相同**；Linux/GCC 加 `target_clones("default","avx2")` 运行时分发，`-ffp-contract=off`（既有构建参数）保证各 clone 逐位一致。ABI 保持 1：对外距离值仍由 Python `math.dist` 复核返回，内核距离仅用于候选选择，其边界歧义由既有的 `1e-12` 相对间隙守卫回退到参考执行器（`vector_index.py:170`）。Windows（MinGW 无 ifunc）编译基线 clone，SSE2 自动向量化仍生效。

未改动：WAL 格式与 fsync 时机、快照失效策略（r3 成果保留，快照构建次数与字节完全一致）、事务/恢复语义。

## 第三轮（同日，第二轮之后）

重新剖析（400 查询 / 100 批写入）：查询侧内核占 50%、storage 链 20%；写入侧 json 解码 16%、fsync 7.6%、WAL 写 6.4%、分词 5%。三项低风险修改：

1. **`minivectordb/storage.py` `write_record()`**：长度头与负载合并为一次 `write_all`，每条记录 syscall 从 2 次降为 1 次；磁盘字节与旧格式完全相同。
2. **`native/exact.cpp`**：内核返回**平方距离**（去掉每行 `sqrt`）。平方距离对真实距离单调，排序与并列关系不变；Python 侧仍用 `math.dist` 复核返回行，边界守卫改为比较平方距离后约保守 2 倍（更常回退到精确执行器），正确性不受影响。
3. **`native/exact.cpp`**：所有指针参数加 `__restrict`，帮助编译器向量化。

测量（宿主机同会话，两次运行）：

| 指标 | 第三轮前 | 第三轮后（两次） | 变化 |
| --- | ---: | ---: | ---: |
| 写入 | 1.4145s | 1.2669 / 1.3051s | -7.7% ~ -10.4% |
| 查询 | 1.6662s | 1.3963 / 1.3770s | -16.2% ~ -17.4% |
| 恢复 | 0.4512s | 0.4173 / 0.4057s | -7.5% ~ -10.1% |

容器 benchmark（1 轮，镜像 `03f5af68`）：静态查询中位 2.59→2.42ms、过滤 2.12→1.82ms、无过滤 3.03→2.62ms（对比第二轮）；Recall 双组 1.0、结果与重启核对通过、快照构建次数不变。

**写入的容器 A/B 对照**：用当前源码临时构建“旧两次写”镜像（`r3-ab`）与本轮镜像各跑一轮，写入 2.4408s vs 2.4296s——差异在噪声内，确认本轮写入改动无回退；先前观察到的 2.24→2.42 是机器状态波动，不是代码变化。

回归：宿主机 108 套件 + 公开 40 + 独立 P0–P8 全绿；容器 108 套件（17.9s）+ P7 112 + P8 170 全绿。
