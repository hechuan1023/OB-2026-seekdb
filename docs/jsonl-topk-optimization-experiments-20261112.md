# JSONL 请求与精确 TopK 优化实验（2026-11-12）

## 测量范围

基线为已有未提交主键过滤优化镜像 `minivectordb:pk-filter-candidate`（sha256:8805f44ab73d407c739c415f6b245fc5c95fd653aea896768775d0f69e9fe887），不是正式高分版本。所有实验在 Docker Desktop Linux、2 CPU、256 MiB、禁 swap/网络，每轮独立数据卷，10000×128、每批 100 行、1000 次 exact 查询（过滤/无过滤各半，预热 4 次），查询 ID/距离逐条对照真值，写入测量后同卷重启逐条核验 10000 行。每版本每组四轮并轮换执行顺序。T 是宿主逐条端到端管道请求时间之和，B 是容器 ready 之后至末次 sync 期间本机设备 8:64 的 cgroup 读写增量，M 是容器累计峰值，包含辅助采样进程。未验证平台数据设备、写回归属或官方冷热缓存，不能算正式 E。

## JSONL 分段插桩

`.local-jsonl-instrument.py` 包装真实 JSONL serve，并在 pipe 上由 `.local-jsonl-instrument-driver.py --output .local-jsonl-instrument-20261130.json --rounds 1 --queries 1000 --seed 20261130` 驱动。1004 次查询含四条预热；SELECT 累计 SQL parse 0.051689 s，execute_initial 0.036393 s，逐行 next（含首次过滤、原生距离计算等）0.420463 s，行 JSON 序列化 0.014024 s，stdout 写 0.040481 s。所有查询与真值一致。分段有计时包装与嵌套调用开销，不涵盖协议全部阶段、驱动往返、延迟调度或官方平台，不能把数字相加推断正式得分或物理上限。

## 候选与对照结果

延迟读取：小于候选堆边界的行才读取主键；维持精确距离并列主键排序。29 项向量定向测试通过，随机多维、选择集原生位置和距离字节 SHA-256 与基线一致。两 seed 查询方向相反、幅度与噪声接近，回退。

JSONL 合并：将响应头加入首个 64 条有界输出块；空结果、63/64/65/130 行边界、Unicode 的临时定向测试通过。两个 seed 查询均变慢，不能仅凭这些数据断言是 pipe 调度或其他特定原因；回退该改动和专门临时测试。

FMA 提前终止：仅对 128 维，当部分非负平方和大于堆边界时停止当前候选计算；其余维度和便携路径沿用原方法。29 项向量定向测试通过，多维随机输入的原生位置与距离字节哈希同基线一致；第一组查询中位数改善约 5.4%，第二组基本持平。样本不能证明所有边界及稳定收益，精确排序是功能前提，因此回退。

## 结论

三个候选没有达到稳定且全面改善的保留标准，全部回退；此前主键范围过滤优化及用户既有未提交材料保留。现有基线的 159 项 Docker 单测、20/20 官方公开用例、64 MiB 压力及强杀恢复记录见 `pk-filter-out-of-core-experiment-20261112.md`。本轮无正式提测、提交或推送；不能据本机结果推算官方 E。
