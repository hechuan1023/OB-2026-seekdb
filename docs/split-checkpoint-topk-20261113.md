# 拆分 64 维检查点的 exact TopK（2026-11-13）

本实验在 `19b542e566341945fa082694904cdf950e4b1ef6` 的 64 维有界
exact TopK 基础上，把检查点从每 16 维执行一次的条件判断改为：

1. 连续扫描前 64 维；
2. 检查一次部分平方距离下界；
3. 继续扫描剩余维度。

累加顺序、0.1% 边界余量、float32 候选内核和最终有序 double 复核均未改变。
本页记录 Docker Desktop 本地对照，不是官方 T/B/M、E 或正式准入结果。

## 实现

原实现把 `j == 64` 和阈值条件放在 16 维循环内部，因此 128 维行会重复执行
八次与检查点有关的判断。新实现先扫描到不超过 64 维的最后一个 16 维块，
在循环外执行一次下界检查，再进入没有检查点分支的剩余扫描循环。

对于 128 维特化路径，编译器可以把检查点固定为 64。维度不足、阈值尚未建立、
非 AVX2/FMA 路径和边界回退行为保持不变。

候选/基线比值的中位数。

| 集合 | 基线中位 | 候选中位 | 配对比值 | 候选更快轮次 |

| 2,000 行过滤 | 14.338 ms | 12.350 ms | 0.815428 | 9/9 |

两个场景的所有轮次和结果均一致。该微基准说明重复分支确实进入了热循环；
完整 JSONL 仍需单独测量。

## 结论与边界

保留该改动。五种子的总查询配对中位数均小于 1，汇总中位数为 `0.984013`；
无过滤改善稳定，有过滤基本持平。该改动只移除 AVX2/FMA exact TopK 候选扫描
热循环中的重复检查点判断，不改变 SQL、事务、恢复、过滤顺序或最终精确结果。
本地结果不能单独预测官方性能 E。
